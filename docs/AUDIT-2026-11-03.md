## A. Cycles: work done twice, or done when nothing needs it

1. **One reader per controller (Controllers).** The same device is opened and polled on its own by Button2Key (every
   4 ms), ForzaWheel (1 ms while feeding), SimEffects → Input Overlay (5 ms), Gaming → Devices (33 ms) and Core's
   controller shortcuts (25 ms, through winmm). Make it a shared pool: one open reader per device, read once per tick
   at the fastest rate anyone asks for, and every module gets the same reading. Core's shortcut buttons would read from
   it too when it's running. Biggest saving for anyone with a wheel rig. Risk: the rig's driver crashes (one DirectInput
   lock already), so it needs testing on GAMER11.
2. **One game watcher (Core `RunningPrograms`).** The process list is shared already, but 7 timers each check it on
   their own: Button2Key (2 s, in its loop), Button2Key Remote (2 s), ForzaWheel (2 s), SimEffects Profiles (3 s),
   Mini Mirror (2 s), Resizer (its poll rate), and Video (1 s, which also opens the front process every second).
   Replace them with `RunningPrograms.Watch(programs, started, stopped)`: one timer, and an event only when something
   changes. Also move the "switch on when the game starts, and off only if the game switched it on" rule there, written
   once (Button2Key, Button2Key Remote and ForzaWheel each have their own copy). LibreHardwareMonitor's
   `ProcessRunning` (`Process.GetProcessesByName`) moves to it as well.
3. **One screen capture (DaisysApp.Shared).** AmbiLight (`ScreenSampler`), Mini Mirror (`Capture`) and Recording
   (`Recorder`) each create their own D3D11 device and Desktop Duplication of the same display. `DuplicateOutput1` is
   copied word for word between them. With AmbiLight and a mirror on, the GPU copies every frame twice. Make it a
   shared capture per display that hands each user the frame texture.
4. **One system sampler (DaisysApp.Shared/Hardware).** Performance (always on), Video's overlay (`Telemetry`), its
   `RecordingImpact` and Stress Tests' `Monitor` each run their own PDH query, NVML and `GlobalMemoryStatusEx` for
   CPU, GPU and RAM. Make it a ref-counted sampler that runs once a second, like `SensorHub` already is, with
   Performance as one of its users. The machine description is in the same state: Performance's `SystemInfo`, Stress
   Tests' `SystemSpec` and Video's GPU list all read the CPU name, cores, RAM and DXGI adapters, so that becomes one
   `SystemSpec`.
5. **Input Overlay widgets render every frame.** `OverlayWindow` and `DashWindow` hook `CompositionTarget.Rendering`
   for as long as they're visible. That makes WPF redraw at the monitor's refresh rate (144–240 Hz) even when no game
   is running, and the Dash redraws even when nothing changed. Unhook it when there's no data or the game is paused,
   and redraw only on a new frame.
6. **The Shaker's device volumes poll every 100 ms.** `DeviceVolumes` compares its settings with Windows ten times a
   second while the Shaker is on, and looks for missing devices every 3 s. Send the change when the slider or shortcut
   changes it, and use `DeviceService`'s device notifications for plugged-in devices. Audio's `DeviceVolumeRow` wraps
   an endpoint's volume and mute the same way, so that becomes one `EndpointVolume` in Shared/Audio.
7. **Performance wakes every 250 ms** but samples once a second (and processes every 10 s): it should sleep until
   the next sample is due. Its Processes page also takes its own Toolhelp snapshot just for parent ids;
   `RunningPrograms`' snapshot can carry those too.
8. **Video runs a 1 s background tick and a 500 ms UI tick all the time,** even with the frame counter off and the
   overlay hidden. Stop both when nothing needs them (the same test `UpdateFrameMonitor` uses).
9. **Button2Key's loop allocates every 4 ms** (`runs.GroupBy(...)` each tick). Group the runs once, when the profile
   loads. Small.
10. **One device-change notice (Core).** Gaming → Devices (`HotPlug`) and USB Monitor (`DeviceNotificationWindow`,
    plus a 30 s poll) each register for WM_DEVICECHANGE. Core's controller buttons retry lost controllers on a timer,
    and Arduino retries its port every 3 s. Make it one Core `DeviceChanges` event that Controllers uses to rescan, so
    every module rescans together when something is plugged in.
11. **Brushes and pens.** `Ui.Brush` returns an unfrozen brush, and five modules have their own copy (iRacing `Hex`,
    RGB `Brush`, Analysis `Frozen`, Shaker `Frozen`, DiskMark `Hex`). Make Core's frozen and cached, and delete the
    copies. Devices' `DeviceArt`, Calibration's `Visuals` and the overlay's trace create new pens and typefaces on
    every draw (up to 30 a second), so cache those too.

## B. Duplicate code that goes to Core

12. **Win32 declarations in Core (`Win32/Native`).** These are each declared in several modules: `IsWindowVisible`
    ×8, `SetWindowPos` ×7, `GetWindowRect` ×7, `GetWindowThreadProcessId` ×6, `GetWindowLongPtr` ×6, `EnumWindows` ×5,
    `GetForegroundWindow` ×5, `GlobalMemoryStatusEx` ×4, the GDI DC set ×4, `DwmGetWindowAttribute` ×3 and `SendInput`
    ×2. `timeBeginPeriod` ×3 becomes a ref-counted `HighResTimer.Hold()`.
13. **Joystick plumbing in one place.** `joyGetPosEx`, `JOYINFOEX` and the registry OEM-name lookup are in both Core's
    `ControllerButtons` and Button2Key's `Joysticks`. `DirectInput8Create` + `IDirectInputJoyConfig8` are in both
    `ControllerButtons` and Devices' `JoyOrder`. Matching a joystick number to its device is written three ways (Core
    by JoyConfig GUID, Button2Key by VID/PID and order, Devices). The two fake-controller copies
    (`DAISYSAPP_FAKE_CONTROLLER`, Calibration and Devices) go too. As a bonus, Button2Key's profiles could then follow a
    controller when Windows renumbers it, as shortcuts do since 3.37.15.
14. **The game-list editor.** The typed box, the "running programs" menu and `AddGames` are copied in Button2Key,
    Button2Key Remote, ForzaWheel and Mini Mirror. Replace them with one Core `Ui.ProgramList`.
15. **Debounce and "save soon".** About 15 hand-made one-shot timers do this: Mini Mirror, B2KR Editor, Shaker,
    KnownDeviceStore and SimProfiles saves, plus refresh/preview/search/typing delays. Add Core `Debounce` and
    `JsonStore.SaveSoon`. Also make `JsonStore.Save` atomic (write to .tmp, then move): it writes in place today, while
    four other places do their own .tmp.
16. **Timers that run while shown.** About 25 views do `IsVisibleChanged` → Start/Stop by hand. Replace them with Core
    `Ui.Every(element, interval, tick)`.
17. **Daily history files.** PerfLog, SensorLog, GameLog, Ping, Events, Speed Test, TraceLog and LapTracker each have
    their own day-file naming, Days/SizeBytes/Cleanup/DeleteAll, number formatting and per-slot averaging. Replace them
    with a Core `DailyLog`, which Settings → Storage can use too.
18. **One HTTP client.** Support has five `MakeClient()` copies (IpDetails, NetInfo, Discovery, the map, DeepScan),
    plus iRacing's, HardwareMonitor's and Updates' two. Replace them with Core `Http.Client`.
19. **Open and Copy.** 31 `UseShellExecute` starts in 24 files, although Core has `Ui.Open` and `ShowInExplorer`. There
    are 11 clipboard writes, and only two of them retry. Use `Ui.Open` everywhere and add a `Ui.Copy` that retries.
20. **Video's `HistoryGraph`** is a simple line graph with hover, which Core's `LineGraph` already is: use that.
    iRacing's and Forza Analysis' charts are specialised: keep them.
21. **Core Audio COM declarations** (`IMMDeviceEnumerator`, `IMMDevice`) are in Core `AppAudio`, Audio's `Bluetooth`
    and `MicAgc`: keep one copy. Small.
22. **One encrypted connection layer.** Core `Server/Wire` and B2KR's `ButtWire` (and AI's `Remote`) each frame by
    length and encrypt with AES-GCM and PBKDF2. Move the framing and crypto to Core and keep B2KR's bytes exactly the
    same (the Android app). AI's part waits for the AI refactor.
23. **NVIDIA's nvapi64** is loaded separately by RGB's `NvidiaGpus` and the new `Support/Gpu/GpuController`. Make it
    one `NvApi` next to `Nvml` in Shared/Hardware. That folder is uncommitted work from another session, so do it there
    or after it lands.
24. **`Support/Gpu`'s 1 s telemetry timer** starts when the view is built and never stops while it's hidden. Gate it
    on being shown, unless the fan curve needs it running (also the other session's work).

## Kept on purpose (not recommended)

- Calibration's own DirectInput devices: it needs raw and calibrated modes.
- Screen's low-level hooks: those are its features, not shortcuts.
- The widgets' Ctrl+Shift check (150 ms): it only runs while a widget lets clicks through, and costs almost nothing.
- Hotkeys' held-key check: it only runs while a key is held.
- Mini Mirror's mirrors and Video's game overlay: they aren't widgets, by design.
